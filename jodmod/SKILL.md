จดหมด (Jodmod) — สรุปฟีเจอร์ปัจจุบัน
อัปเดตล่าสุด: 2026-09-13 — อ่านจบใน 3 นาที

1. ภาพรวม
จดหมด = เว็บแอปจดรายรับ-รายจ่าย (finance tracker) ล็อกอินผ่าน LINE Login หรือ Google Login
ทุกบัญชีมี tenant (พื้นที่ข้อมูล) ของตัวเอง 1 อัน และรองรับ multi-tenant แบบ "บ้าน" (family)
LINE OA เป็นช่องทางเสริมสำหรับเชื่อมบัญชี/คุยกับบอท

2. Auth & Account
Login 2 ทาง: LINE Login และ Google Login (OpenID Connect ทั้งคู่)
แยกบัญชีตาม provider — LINE กับ Google คนละ user/tenant กันแม้ email เดียวกัน (ไม่ลิงก์ด้วย email)
บังคับด้วย UniqueConstraint(auth_provider, provider_user_id)
Logic สร้าง user/tenant ใช้ helper กลาง upsert_user_and_tenant() ร่วมกันทั้งสอง provider
1 user = 1 tenant สร้างอัตโนมัติในทรานแซกชันเดียวตอน login ครั้งแรก
Session: Flask-Session (filesystem backend), cookie HttpOnly + SameSite=Lax + Secure (เมื่อไม่ debug)
ป้องกัน CSRF ด้วย state + nonce เก็บฝั่ง server ระหว่าง OAuth flow (ไม่ฝากไว้ที่ client)
หน้า /login เป็น chooser (login.html) ให้เลือก LINE หรือ Google
3. Tenant / Home (family)
บัญชี premium สร้าง "บ้าน" ได้ (POST /api/homes), บัญชี free ทำได้แค่ join ผ่าน invite token เท่านั้น
Owner บ้านออก invite token (มีวันหมดอายุ, ใช้ครั้งเดียว) ผ่าน POST /api/homes/<id>/invites
Join บ้านด้วย token ผ่าน POST /api/homes/join
ทุกกฎ premium/สิทธิ์บังคับฝั่ง server ทั้งหมด (ไม่พึ่ง frontend)
ลบบ้าน — owner ลบบ้านได้จากหน้า workspace ("danger zone"), ลบแบบ atomic ทั้ง transactions/categories/budgets/goals/
invites/memberships ในทรานแซกชันเดียว (rollback ถ้า commit ล้มเหลว, ไม่ทิ้งข้อมูลค้าง); แผงยืนยันซ่อนตอนโหลดและหลังยกเลิกได้ถูกต้อง
4. Finance API (tenant-scoped ทั้งหมด)
transactions — CRUD + list (filter type/category/ช่วงวันที่, pagination)
categories — list/create ตาม tenant, แยกตาม income/expense
budgets — CRUD ตามเดือน (period YYYY-MM) พร้อม progress คำนวณยอดใช้จริง
daily_budgets — งบรายวันต่อบัญชี/บ้าน (budget_date ตาม Asia/Bangkok) ตั้ง/ดู/ลบได้ผ่าน API และ LINE OA พร้อมคำนวณใช้ไป/คงเหลือ/เกินงบจากรายจ่ายจริงของวันนั้น
goals — เป้าหมายการออม (target/saved amount, due date)
summary — สรุปรายเดือน (income/expense/balance, by category, เทียบเดือนก่อน)
dashboard — ภาพรวม (balance, รายการล่าสุด, top categories, budget progress, insight ข้อความ)
เงินเก็บเป็น Numeric (Decimal) เสมอ ไม่ใช้ float
จดและแก้ไขรายรับ/รายจ่ายจากหน้าเว็บได้แล้ว: ทุกกล่องบัญชี (ส่วนตัว + บ้านทุกหลัง) มีปุ่มหลัก "+ จดรายการ" เปิด modal
ที่ล็อกบัญชีปลายทางชัดเจน (สลับรายรับ/รายจ่าย, จำนวนเงิน, โน้ต, วันที่ default วันนี้ timezone Bangkok, หมวดหมู่ไม่บังคับ
โหลดตามประเภท+บัญชี) → ยิง POST /api/transactions พร้อม X-Tenant-ID ของบัญชีนั้น → รีเฟรชยอดกล่องทันที
รายการล่าสุดและรายการใน modal รายวันมีปุ่ม แก้ไข ข้างปุ่มลบ ใช้ modal เดิมในโหมดแก้ไขและ prefill ประเภท/จำนวน/โน้ต/วันที่/หมวดหมู่
ครบถ้วน → ยิง PATCH /api/transactions/<id> ภายใต้ tenant เดิม; ล้างโน้ตหรือหมวดหมู่ให้เป็นค่าว่างได้ และรีเฟรชสรุป/ปฏิทิน/
รายการรายวันที่เปิดอยู่หลังบันทึก
ยอด "คงเหลือ" ติดลบแสดงเครื่องหมาย − ถูกต้อง (เดิมโชว์ค่าสัมบูรณ์ทำให้เข้าใจผิด)
เงินผูกกับ Tenant (บัญชี) ไม่ได้ผูกกับ User โดยตรง:
บัญชีส่วนตัว = ข้อมูลการเงินส่วนตัวของผู้ใช้คนนั้น
บัญชีบ้าน = เงินกองเดียวที่สมาชิกทุกคนในบ้านใช้ร่วมกัน (owner/member ไม่ได้แยกกอง)
ทุก request เลือกบัญชีด้วย X-Tenant-ID และอนุญาตผ่าน TenantMember เท่านั้น
หมายเหตุที่รู้แล้ว: dashboard frontend ยังไม่ได้ส่ง X-Tenant-ID ไป /api/dashboard จึงอาจแสดงบัญชีส่วนตัวแม้กำลังดูบ้าน
5. User Role + Admin Panel
User มี role เดียว ระดับ global: user | admin (ไม่ใช่ RBAC หลายระดับ/per-tenant)
Bootstrap admin คนแรกผ่าน env ADMIN_EMAILS (comma-separated) — auto-promote ตอน login ถ้า email ตรง
ใช้ได้เฉพาะ Google login เท่านั้น เพราะ LINE Login scope ปัจจุบันไม่มี email
Admin panel ที่ /admin: ค้นหา/filter (email, accountType, role, isSuspended)/pagination รายชื่อ user,
ดู tenant/home ของ user, toggle accountType (free/premium) และ isSuspended — ไม่รองรับเปลี่ยน role ผ่าน UI นี้
(กัน self-lockout ตอนไม่มี admin เหลือ, เป็น backlog เฟสถัดไป)
Suspend มีผลทันทีทุก request (เช็คสดจาก DB ไม่ cache)
Non-admin ที่พยายามเข้า /admin ถูก redirect กลับ workspace ตัวเอง (/app/<tenant>) ไม่ใช่หน้า error
ดูบ้านทั้งหมด + สมาชิกในบ้าน (read-only): GET /api/admin/homes (ค้นหา/pagination) และ
GET /api/admin/homes/<id> (รายละเอียด + สมาชิกทุกคน) — มองข้าม tenant boundary โดยเจตนาผ่าน require_admin เท่านั้น,
ไม่โชว์ข้อมูลการเงิน, แยก userRole (global) กับ membershipRole (ในบ้าน) ชัดเจน
6. LINE OA — เชื่อมบัญชี, จดรายรับ/รายจ่ายจากข้อความ และจดรายจ่ายจากสลิป
POST /webhook/line — public endpoint, verify X-Line-Signature (HMAC-SHA256 ด้วย Messaging channel secret) ก่อนประมวลผลทุกครั้ง
Resolve source.userId (lineUid) → User ผ่าน LineLink:
บัญชี LINE-login → LineLink ถูก upsert อัตโนมัติตอน login
บัญชี Google (หรืออื่นๆ) → เชื่อมด้วย one-time code ที่หมดอายุและ lock หลังลองผิด 5 ครั้ง
หน้าเชื่อมบัญชีมี 2 ทาง: /app/<tenant>/link-line และ /link-line; ผู้ส่งที่ยังไม่เชื่อมจะได้รับลิงก์กลับไปเชื่อมบัญชี
หน้า workspace มีบล็อก เพิ่มเพื่อน LINE OA ในการ์ด "ทางลัด": แสดง QR จาก /assets/mascot/jodmod_lineoa.png, LINE ID @407lfmhg
และปุ่มเปิด https://lin.ee/86HUYyN โดยตรง; QR ขนาด 264x264px; desktop วาง QR/ข้อความ 2 คอลัมน์ และมือถือเรียงแนวตั้งโดยไม่เกิด horizontal overflow
จดรายรับ/รายจ่ายด้วยข้อความในแชท: หลังเชื่อมบัญชีแล้ว พิมพ์ได้หลายรูปแบบ เช่น รับ 500 เงินเดือน,

14. คำถามที่พบบ่อย
ทำไมตัวเลือกบัญชีรับสลิปเป็นสีเทา?
ยังไม่ได้เชื่อม LINE OA ให้กด เชื่อม LINE OA ก่อน แล้วกลับมาที่ Workspace อีกครั้ง

ทำไมส่งข้อความแล้วระบบไม่บันทึก?
ตรวจสอบว่าข้อความมีทั้งประเภทและจำนวนเงิน เช่น รับ 500 หรือ จ่าย 120 หากข้อความไม่ชัดเจน ระบบจะไม่เดา

ทำไมส่งสลิปแล้วระบบไม่บันทึก?
ภาพอาจไม่ชัด หรือผล OCR สองรอบไม่ตรงกัน ให้ส่งภาพต้นฉบับหรือ screenshot ที่คมชัดกว่าเดิม

ทำไมรายการจาก LINE เข้าผิดบัญชี?
ตรวจสอบส่วน บัญชีรับสลิปจาก LINE ใน Workspace แล้วเลือกบัญชีใหม่ หรือเปิดโหมด ถามทุกครั้ง

ทำไมยอดคงเหลือติดลบ?
ยอดคงเหลือคำนวณจากรายรับลบรายจ่าย หากรายจ่ายมากกว่ารายรับ ระบบจะแสดงเครื่องหมายลบตามจริง

ทำไมต้องเข้าสู่ระบบใหม่หลังระบบอัปเดต?
ระบบ session ปัจจุบันยังจัดเก็บอยู่ใน backend container เมื่อมีการ rebuild หรือ restart session เดิมจะหมดอายุ
